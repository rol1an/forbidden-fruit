# Mode 选择（grinding vs fusion）

> **何时读**：用户首次触发 yanyu-dialogue 时——agent 必须先判断走哪个 mode。

## 关键词字典

### → grinding mode

研磨 / 深挖 / 学透 / 苏格拉底 / 引导提问 / 被问住 / 自己想 / 把我问住 / 别给我答案 / 让我自己想 / 反喂答案 / 不要总结

**+ 通常伴随**：具体文章 URL 或主题词（"我想学 RAG 那篇" / "深挖 multi-agent"）

### → fusion mode

跨界 / 碰撞 / 收敛 / devil's advocate / 质疑我 / 杠我 / 灵感 / 我想做个 / 有个想法说不清 / 模糊的灵感 / 创意 / 给我一些不一样的视角

**+ 通常伴随**：模糊的创意描述（"我想做一个工具帮人..." / "我有个关于 X 的想法但说不清")

### → 不明确（必须反问）

用户只说"砚友" / "/yanyu-dialogue" / "你好" / 没给关键词 → **不要瞎猜**，直接反问。

## 反问话术（用户输入不明确时）

```text
你今天想用砚友的哪一种模式？

🪨 **研磨模式**：你已经看过/收藏过某篇文章/主题，想被我用苏格拉底式提问引导你学透
🍎 **研创模式**：你有个模糊的创意或困惑，想被我反复质疑、跨界碰撞，直到自己想清楚

直接告诉我"研磨 <文章/主题>"或"研创 <你的模糊想法>"。
```

## 边界 case 处理

### Case 1：用户说"研磨"但没给文章

→ 走 grinding mode + Step 1 主动推荐：基于画像选"掌握度低 + 卡壳点未消化"的文章
- 话术："看你画像里 RAG 召回分层 还没消化，今天研磨这个？我先抛第一个问题..."

### Case 2：用户说"我想做个 X"但 `domain_familiarity_tags < 3`

→ 想走 fusion 但知识库储备不够。
- 话术："你的知识库还太小，跨界碰撞抽不出有戏剧性的组合。建议先用 yanyu-import 多导入几篇不同领域的文章，攒到 3 个以上不同标签再来。"
- **不要降级到 grinding**——fusion 是用户主动选的，强行换 mode 会让用户体验割裂

### Case 3：用户研磨到一半突然说"那我想做个 X 怎么办"

→ 这是 mode 切换信号。
- 话术："听起来你冒出创意了——我们把研磨先暂停（这次的 stuck points 我已经记下来），切到研创模式跟你碰一下这个想法？"
- 用户点头 → 跑 profile_write.py 落盘 grinding session → 切 fusion mode → 重新跑 fusion Step 1-2

### Case 4：用户说"用砚友"+ 给了文章 URL（grinding 信号强）但其实他想要的是创意（fusion）

→ 这种情况罕见但可能。
- 默认走 grinding（关键词显式）
- 如果第一轮 agent 抛钩子问题后用户回复偏向"我想用这篇文章的方法做个 X"——切 fusion，话术同 Case 3

## 不应该出现的情况

❌ agent 自作主张猜用户想要哪个 mode 然后直接开干（用户体验断裂）
❌ 同一次对话频繁切换 mode（每次切换都要落盘 + 重置 stage）
❌ 把两个 mode 揉成一种"研磨 + 研创"四不像（违反单一职责）

## 实现提示给 agent

对话首回合 agent 内心 self-prompt：

```
1. 看用户首句话有没有命中 grinding/fusion 关键词字典
2. 看用户有没有给具体文章 URL/主题词 vs 模糊创意
3. 如果信号清晰 → 直接进对应 mode + Step 1
4. 如果不清晰 → 用上面的反问话术，等用户明确
5. 任何时候都禁止"我自己也不确定你要哪个，那我两个都做一点"——必须二选一
```
