# description 字段调优指南

> **何时读**：部署前 10 条触发率测试 <80% 时，按本指南重写 description。

## 触发率公式

```
触发率 = 命中 Skill 的次数 / 测试用例总数
```

10 条不同口吻的真实用户输入 ≥ 8 条命中 = 合格（≥80%）。

## 写错的常见症状 → 处方

| 症状 | 原因 | 处方 |
|---|---|---|
| 用户说"导入文章"没触发 | description 用"微信公众号"过窄 | 加同义词："文章 / 微信文章 / 公众号文章 / 收藏的文章" |
| 用户说"砚友导入"没触发 | 缺产品名关键词 | 显式加产品名："砚友、yanyu-import、forbidden fruit" |
| 用户说"把这个链接存到飞书"没触发 | 缺意图动词 | 加动词："存、入库、保存、收藏、整理、归档、import" |
| 用户说"去广告这篇文章"没触发 | 缺特色卖点关键词 | 加特色词："去广告、剔除营销、去噪、脱水" |
| 用户给 URL 没说别的，没触发 | description 没暗示"URL 即触发" | 加场景描述："当用户提供 mp.weixin.qq.com 链接..." |

## 砚友 description 模板（拷贝改）

```yaml
description: "当用户提供微信公众号文章 URL（mp.weixin.qq.com），希望去掉广告与营销号噪音、按知识结构重组并入库到飞书知识库时使用。会保留原作者的强力标记（加粗/彩色字体）、按 4 色约束做美学排版、自动在 Bitable 索引表里做双向链接缝合。触发词：微信文章、公众号文章、收藏导入、知识入库、去广告、把这篇文章存到飞书、import-wechat、砚友导入、yanyu-import。"
```

三要素自检：

- [ ] **触发场景**：明确说了"当用户...时使用"
- [ ] **特色卖点**：去广告 / 强力标记保留 / 4 色排版 / 双向链接 至少 2 项
- [ ] **关键词清单**：用户最可能说出的 6-8 个表述都铺在 description 里

## 长度约束

- **不少于** 50 字：太短关键词不够，触发不到
- **不多于** 250 字：太长冲淡信号，模型抓不到重点
- **1-2 句话**：用顿号/逗号连接多个关键词，最后一句明示触发词清单
