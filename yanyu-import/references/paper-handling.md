# 论文类文章特殊处理

> **何时读**：Step 3 知识重构时识别出原文是严谨的论文介绍（含数学推导、模型架构图、实验结果图）。

## 一、公式与图表必须保留

**不得简化、省略、替换为文字描述**。理由：论文的精确性来自数学和图表，丢了 = 失去原研究的可验证性。

| 类型 | 飞书 DocxXML |
|---|---|
| 行内公式 | `<equation>LaTeX</equation>` |
| 独立公式块（推导步骤、重要公式） | `<equation-block>LaTeX</equation-block>` |
| 图片 | `<img href="完整URL" caption="语义描述或原文图注"/>` |

**图片处理**：微信图片直接用 `<img href="完整URL"/>` 嵌入——飞书 API 会自动拉取并上传，**无需本地下载再上传**。`href` 必须是从 `data-src` 提取的完整地址（保留 `?wx_fmt=png&from=appmsg`，`&amp;` decode 成 `&`），不能截断。

## 二、图片放置顺序

严格按原文位置——Step 1 已建立的「文字块 + 图片」有序列表是唯一依据。**禁止凭感觉重排**——会导致图文错位，读者无法跟随原作者的论证节奏。

## 三、图注 caption 规则

每张图的 `caption` 写原文图注或语义描述：

```xml
<img href="..." caption="公式①：全局轨迹奖励函数"/>
<img href="..." caption="图 3：消融实验 — 移除模块A后准确率下降 12%"/>
```

caption 让扫读者不用点开图也能知道在讲什么。

## 四、实验图必须附解读段落

每张实验图 / 消融图下方必须有一段解读，说明图展示的规律：

- 简单任务 vs 复杂任务的差异
- 关键拐点
- 与 baseline 的差距

**不能只贴图**——读者会困惑"作者想表达什么"。

## 五、多方案对比要分段

如果原文做"RAG vs RL vs 本文方案"这类多方案对比，**各方案分段单独分析**局限性，不要混在一起笼统描述。

```markdown
### 方案 A · RAG
局限性：...

### 方案 B · RL
局限性：...

### 本文方案
解决了 A 和 B 的哪些痛点：...
```

## 六、核心设计点要附"为什么这样能解决 X" callout

```xml
<callout emoji="💡" background-color="light-yellow" border-color="yellow">
  <p><span text-color="blue">为什么后验概率能解决信用分配难题</span></p>
  <p>用直觉语言解释技术动机...</p>
</callout>
```

读者读懂了"为什么"才能复现"怎么做"。
