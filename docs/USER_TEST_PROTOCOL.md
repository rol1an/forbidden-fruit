# 5-30 真朋友测试 Protocol

> 2026-05-22 起搭建 · 决策 4 钉死的"全项目最关键节点"配套材料。
>
> 主对话铁律：**不是给作者自评双重幻觉填数据**——是逼真实用户给出"这玩意儿到底有没有用"的硬信号。

---

## 1. 为什么必须做

**REVIEW_001 三个致命问题之一**：「用户悟到」主观成功标准 + 作者自评 = 双重幻觉。砚友决策 4 的回应：**5-30 之前 3 个朋友独立测试**，破除作者自评。

**5-30 这条线是项目生死线**——22 天里唯一能告诉你"砚友到底成不成立"的信号源。等 6-10 才测来不及调 prompt。

## 2. 招募门槛

**人数**：3 人（**不能少于 3，可以多于 3**）

**关系门槛**：

- 关系熟到**敢请 ta 给你 30 分钟**且 ta 不会因为客套乱填问卷
- **至少 1 个非 AI 圈**（关键）：必须是不写代码 / 不调 LLM / 不天天聊 RAG 的人。AI 圈朋友会因为"对你产品有滤镜"给假阳性反馈
- 其他 2 个可以是 AI 圈, 但**至少 1 个跟你不熟到会客套敷衍**的程度——找那种会直接说"这破玩意儿不好用"的人

**避免**：

- ❌ 跟你天天讨论砚友设计的人（已被你叙事 prime 过）
- ❌ 对 AI 持极端立场的人（极赞 / 极厌都不行, 反馈会偏极端）
- ❌ 30 分钟硬挤的人——测的时候会想着下一件事, 反馈浅

## 3. 时长承诺

向朋友承诺**30 分钟**, 实际内部 buffer 给到 40 分钟（朋友想多探讨可以接, 想 25 分钟跑也接受）。

**绝不**：朋友抱怨"还要继续吗" → 立即收尾走问卷, 不强求做完两个 mode。

## 4. 测试结构（每个朋友, 30 分钟）

| 分段 | 时长 | 内容 | 主持人（你）做什么 |
|---|---|---|---|
| 介绍 | 0-3 min | 30 秒说明砚友是反 AI 喂答案的学习工具, 不要展开哲学 | 见 USER_TEST_SCRIPT.md §介绍 |
| Grinding | 3-15 min | 朋友选一篇 ta 熟悉主题的文章（你提前准备 3-5 个候选）跟砚友研磨一次 | 旁观, **不要插嘴解释**, 朋友卡死也忍住 |
| Fusion | 15-27 min | 朋友抛一个 ta 最近的模糊想法, 跟砚友碰一次 | 同上, 旁观 |
| 问卷 | 27-30 min | 朋友答 5 题（口头 + 你笔录, 或扫码飞书表单） | 见下方 §5 题问卷 |

**Buffer 处理**：

- 朋友 grinding 5 分钟就觉得"我懂了"想跳 → 接受, 立即上 fusion
- fusion 卡死 5 分钟没收敛 → 接受, 立即上问卷
- 朋友想多聊 → 30 分钟硬刹车（一旦放任就再也回不到 25 分钟主线）

## 5. 5 题问卷（决策 4 已定）

完整原文摘自 PLAN_v2 §决策 4：

1. **你被问住过吗？被问住时是什么感觉？**
2. **agent 拒绝直接给答案，你想砸键盘吗？**
3. **最后你有"我悟到了"的瞬间吗？发生在哪一轮？**
4. **agent 的提问，有没有让你想到自己之前没想过的角度？**
5. **如果朋友跟你描述这个产品，你会推荐给谁？**

**主持人记录铁律**：

- 用朋友**原话**记, 不要润色（润色 = 加你的滤镜 = 双重幻觉回来）
- 朋友说"还行 / 一般"等糊弄答案 → 追问"还行是指 X 还是 Y"
- 朋友说话**情绪起伏**的地方专门标记（一句话写"这里 ta 笑了 / 这里 ta 皱眉了"）——情绪信号比文字信号信息量大

## 6. 决策 7 测点（hint laddering + 砚石痕迹专项）

5-22 决策 7 上线了两个新机制——必须在朋友测试里专门观察：

| 机制 | 主持人专项观察 |
|---|---|
| **hint laddering L1/L2** | 朋友被问住时, agent 是不是真的给了 focus hint? L1/L2 的"中文范畴弱形状"提示朋友能不能接住? |
| **L3 open original** | 朋友主动要去飞书查阅原文了吗? 如果有, 朋友回来后**用自己的话**复述了, 还是直接念原文? |
| **砚石痕迹 callout** | 朋友看到 `🪨 第 A 阶段 → 第 B 阶段` 这种 callout 时有反应吗（笑 / 困惑 / 忽略）? 如果朋友问"我现在到第几了" agent 怎么应对（应该反问"是更深还是更浅"）? |
| **L3 频次** | 朋友这次研磨触发了几次 L3? 设计上 L1/L2 应覆盖 ≥80% 卡死案例, L3 ≥2 次是 prompt 失败信号 |

主持人在朋友走后立即抓 session.json 跑 `python3 -m eval.judge --session session.json --mock`, 看 `_ladder_stats` + `_inkstone_stats` 字段实际触发情况 vs 朋友主观体感是否对齐。

## 8. 失败兜底

| 症状 | 应对 |
|---|---|
| 朋友 5-29 临时鸽 | 不强求, 找备胎 / 6-2 ~ 6-3 顺延（**不要等齐 3 人**, 1 人也比 0 人有信号）|
| 朋友测一半跑了 | 已收集的部分照录, 标注 `incomplete=true` |
| 朋友极度负面 / 觉得 agent 烦 | **不要辩护**, 原话记下来, 这是最珍贵的信号 |
| 朋友极度赞扬 | **追问具体哪句话有用**, 否则信号无效（赞扬比批评更容易是社交礼貌）|
| 飞书 API 写不进表单 | 本地 markdown 兜底, 配额回来再迁 |
| 你忍不住给朋友解释 / 辩护 | **闭嘴**。每次开口为 agent 辩护 = 这次测试作废 |

## 10. 不能做的

- ❌ **作者亲自给朋友演示砚友怎么用**——朋友看你用过一次后体感全失真
- ❌ **跟朋友说"这是我做的, 提点建议吧"**——客套反馈混淆信号。说"我在测一个学习工具, 帮我看下" 即可
- ❌ **让朋友测之前先看 README / PITCH.md**——叙事 prime
- ❌ **在朋友答问卷时插话补充**
- ❌ **筛选哪些反馈"有用"哪些"没用"**——全部记录, 6-1 分析阶段再筛
